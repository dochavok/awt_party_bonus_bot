# Requirement coverage

This table traces every requirement in
[party-bonus-bot-requirements.md](../party-bonus-bot-requirements.md) to its tests (TF-3).
Every *must have* requirement has at least one test, or is listed under *Not automated*
with the reason and how it's checked instead. `tests/meta/test_coverage.py` checks both
rules, and checks that the generated part below is up to date.

- **Requirement IDs** come from the requirements tables. The section 4 rules have no IDs,
  so they're listed as `4.1` to `4.13`; `9.1` is the sample game.
- **Milestones** say which milestone implements what the test checks (TF-4). Tests for
  milestones not yet finished run as expected failures. The finished list is
  `finished_milestones` in `pyproject.toml`.
- **After adding or changing tests**, regenerate the second half:
  `uv run pytest --collect-only -q --write-coverage`
- This file is generated documentation, not a test, so the TF-6 check doesn't treat
  changes to it as test changes.
